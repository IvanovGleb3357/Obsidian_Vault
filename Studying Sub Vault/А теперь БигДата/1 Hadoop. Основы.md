## Что такое Hadoop?
Основные принципы:
1. Отправка кода к данным
2. Отказоустойчивость
3. Инкапсуляция сложности реализации распрееделенной системы
4. Горизонтальное масштабировании
## Главные компоненты Hadoop:
	- HDFS - Hadoop Dustributed fileSystem
	- MapReduce - Фреймворк расрпедленной обработки данных
Другие:
	- Hbase: Column-oriented DB, поддержка последовательного и произовльного чтения, поддержка простых запросов
	- Zookeeper: Highly-Available Coordination Service
	- Oozie: Диспетчер задач для Hadoop
	- Pig: Язык обработки данных и среда выполнения
	- Hive: Data warehouse с SQL интерфейсом
**Команды**:
	- hdfs dfsadmin -report - отчет о состоянии hdfs
	- hadoop conf -dump - все настройки хадупа
Мониторинг может осуществляться через UI - ResourceManagerUI и NameNodeUI
**Управление конфигурацией HADOOP**
	- core-site.xml. Настраивает основные параметры Hadoop, такие как насйтрока ввода-вывода, общие для HDFS и YARN.
	- hdfs-site.xml. Настраивает специфичные параметры для hdfs, размер блока, реплицируемость
	- yarn-site.xml. Настраивает параметры ResourceManager, NodeManager

### Демоны HDFS
	![[Pasted image 20240213141725.png]]
**Namenode** - отвечает за:
	- файловое пространство (namespace)
	- мета-информацию
	- расположение блоков файлов
запускается на 1й выделенной машине
**Datanode**
	- Хранит и отдает блоки данных
	- Отправляет ответы о состоянии на Namenode
	- Запускается на каждой машине кластера
**Secondary Namenode**
	- Периодически обновляет fsimage
	- Требует то же железо, что и Namenode
	- !Не используется для high-availability, т.е. это не backup для Namenode

**Как хранятся файлы в HDFS**
Файлы в HDFS состоят из блоков
	Блок - единица хранения данных
	Управляется через Namenode
	Хранится в Datanode

**Файлы и блоки**
Реплицируются по машинам в процессе записи
	- Один и тот же блок хранится на нескольких Datanode
	- Фактор репликации по умолчанию равен 3
	- Это нужно для fault-tolerance и упрощения доступа
	![[Pasted image 20240213142544.png]]

Стандарный размер блоков 64Мб или 128Мб
Основной мотив этого - снизить стоимость seek time по сравнению со скоростью передачи данных (transfer rate)
	time to transfer > time to seek

**Репликация блоков**
1. Namenode определяет, где располагать блоки
2. Баланс между надежностью и производительностью
	1. Попытка снизить нагрузку на сеть (bandwidth)
	2. Попытка улучшить надежность путем размещения реплик в разных стойках
3. Фактор репликации по умолчанию равен 3
	1. 1-я реплика на локальную машину
	2. 2-я реплика на другую машину из той же стойки
	3. 3-я реплика на машину из другой стойки
Репликация может быть настроена как для одного файла так и для всего хадупа. Так например ненужные файлы можно реплецировать лишь дважды, а нужные - чаще.

**Взаимодействие клиента и демонов**
1. Чтение - клиент обращается к Datanode, получать расположения Блоков Файла и считывает их
2. Запись - клиент узнает у Datanode, куда можно расположить? Клиент записывает файл на одну Datanode, далее Datanode передает этот файл на другую Datanode и вконце клиент получает Три подтверждения success.

**Namenode: использование памяти**
Для быстрого доступа вся мета-информация о блоках хранится в ОЗУ Namenode
	Чем больше кластер, те больше ОЗУ требуется
		Лучше миллион больших файлов, чем милларды файлов
		Размер кластера ограничен Namenode


### Типы хранилищ в HDFS и политики хранения данных
**Типы хранилищ**:
1. Горячее хранилище (**Hot Storage**). Данные к которым часто обращаются и которые требуют быстрого доступа. Обычно это критически важные данные используемые в вычислниях  и рассчетах.
	Размещение на **SSD**, для быстроты получения данных при сценриях ежедневных бизнес-процессов.
2. Теплое хранилище (**Warm Storage**). Данные, к которым доступ необходим не так часто, как к горячим данным.
	Размещение на **HDD**, для ежемесячных отчетов
3. Холодное хранилище (**Cold Storage**). 
	Размещение на экономичных хранителях с большой емкостью, ленточные накопители.





## **Map-Reduce в Hadoop**
	![[Pasted image 20240301104933.png]]
**Стадии**:
1) Сплитинг - разделение данных на части (партиции) для их последующей параллельной обрбаботки
2) Маппинг - преобразование данных в пары ключ-значение
	1) record reader - чтение записи исходных данных (HDFS блока)
	2) mapper - вызов функции map(input) -> (key, value)
	3) combiner - предварительная агрегация данных (опционально)
	4) partitioner - вычисление номера reducer-а по ключу
3) Шафлинг - сбор пары ключ-значений, чтобы на одной партиции были пары с одним и тем же ключем
4) Объединени в одну единственную пару
5) Склеивание после редьюса для выдачи рузльтата
### YARN
- Client - запускает задачи
- Resource Manager (RM) - управляет ресурсами на уровне кластера
- Node Manage (NM) - управляет реусрсами на уровне одной ноды
- Application Master (AM) - управлет жизненным циклом приложения
- Container - запущенное приложение
**Как это работает?**
	![[Pasted image 20240301105655.png]]
Допустим с кластером работает **2** клиента, 
	Первый - уже запустился
	Второй - хочет запустить свое
Второй обратится к RM и будет запрашивать ресурсы для своей задачи. Получив разрешение на запуск. Клиент запустит Application Master и Application Master запустится на одной из нод кластера. AM будет независимо взаимодействовать с RM, затем AM выделит контейнер и клиент сможет запуститься
Если вркаце, то
	Он выделяет ресурсы (идешь к RM, RM выделяет контейнер Application Master-у, ему скармливаешь MapReduce done)

**Команды YARN-a**
	- yarn node -list . Показывает список всех нод в кластере.
	- yarn node -status NODE. Показывает статус определенной ноды.
	- yarn application -list. Список и статус запущеных приложений.
	- yarn queue -status QueueName. Выводит информацию о конкретной очереди.
