## HIVE
Apache Hive - warehouse system - надстройка для БД (использует SQL/HiveQL)
**Архитектура**
	![[Pasted image 20240301110217.png]]
	![[Pasted image 20240301110406.png]]
Алгоритм:
	1) Клиент через интрфейс передает SQL запрос драйверу. 
	2) Драйвер преобразовывает SQL запрос в логику необходимую для параллельной обработки задач. 
	3) Полсе этого Драйвер передает этот запрос компилятору для компиляции в MapReduce-задачу на основе данных из Metastore. 
	4) Затем передается задачи в Executer и реузльтат передается клиенту.

В HIVE есть 2 хранилища:
- Метахранилище Hive. Централизованное хранилище для метаданных, включая информацию о базах данных, таблицах и столбцах в кластере Hive. Помогают жффективно работать с данными и хранятся по умолчанию metastore_db.
- Освновное хранилище Hive. Там хранятся фактичсекие даннфе таблиц.
## Hbase
Hbase - column-oriented Хранилище - хранит данные в бинарном виде
	Не предоставляет SQL доступ к ланным
	Поддерживает работу больших таблиц
	Версионирование
	Эффективно работает с ключами
	Работает поерх HDFS и имеет интеграцию с MapReduce
	![[Pasted image 20240301111042.png]]
										![[Pasted image 20240301111416.png]]

**Column Family** - Общие свойсва группы колонок
	- Задается при создании таблицы
	- Агоритм сжатия
	- Количество жизни
	- Время жизни значений - TTL (Time To Live)
	- Хранится в отдельном файле
	- Новые клоонки могут быть добавлены в любое время
**Apache Phoenix** - предоставляет SQL для работы с данными HBase
	- Транзакции
	- Join операции
	- Группировки и агрегации
	- Компилирут запросы в собтвенный API (не использует MR), что позволяет выполнять запросы быстрее
**Cassandra** - колокно-ориентированный тип хранилищ, легко масштабируется, CQL ~= SQL подобный
**ClickHouse** - колонко-ориенитрованный тип хранилищь, SQL-like


## Internal VS External table
Чтобы создать таблицу **Internal**:
	CREATE TABLE 'intrenla_table' (
	'col1' int,
	'col2' string,
	'col3' string)
	ROW FORMAT DELIMITED
	FIELDS TERMINATED BY ','
	STORED AS TEXTFILE;
Чтобы создать **External**:
	CREATE EXTERNAL TABLE 'external_table' (
	'col1' int,
	'col2' int,
	'col3' int)
	ROW FORMAT DELIMITED
	FIELDS TERMINATED BY ','
	STORED AS TEXTFILE;
Если удалить Internal - то она удалиться вместе с данными, однако при удалении External удалится только стрктура и метаданные таблицы, но данные останутся. Поэтому если данными пользуется Spark, Pig, то удаление External table никак не отразиться на других юзерах, однако удаление Internal помешает всем пользоваться данными.
Если таблица **ACID**, то таблица должна быть **Internal**. В остальных случаях лучше **External.**

## Static and Dynamic Partitions (Статическое и Динамическое партиционирование)
**Статическое партиционирование** - партиционирование при создании таблицы.
	CREATE TABLE my_table (
	    id INT,
	    name STRING
	)
	PARTITIONED BY (year INT, month INT)
**Также**, можно добавить партиции с помощью оператора **ALTER TABLE**:
	ALTER TABLE my_table ADD PARTITION (year=2024, month=3);
Используется, когда набор значений партиций заранее известен.

**Динамическое партиционирование** - применяется когда набор значений столбцов при вставке данных в таблицу. Это особенно удобно, когданабор значений партиций динамически изменяется со временем.
	INSERT OVERWRITE TABLE my_table PARTITION (year, month)
	SELECT id, name, year, month FROM source_table;

## HBase
HBase - это распределенная и масштабируемая база данных, основанная на технологии Hadoop и HDFS. Она предназначения для хранения и обработки больших объемов структурированных данных в режиме реального времени. HBase использует модель данных, схожую с Google`s Bigtable`.
**Модель данных**
	1. Данные хранятся в таблицах
	2. Каждая строка имеет Row Key, строки автоматически сортируются по ключу строки.
	3. Столбцы группируются в семейства столбцов (Column Families), которые обхявлены заранее при созании таблицы. В пределах одного семейства столбцов можно динамически добавлять столбцы
**Архитектура HBase**
	1. Master сервер - управляет кластером, назначет регионы региональным серверам, контролирует сбои и обеспечивает балансировку нагрузки
	2. Региональные сервера - обрабатывают запросы к данным, каждый из иних управляет определенным набором регионов
	3. Регионы. Таблица в HBase делятся на регионы для распределения данных по кластеру. Каждый регион содержит строки таблицы в определенном диапазоне ключей
	4. HDFS

4. Apache Ambari - управление и мониторинг настроки кластеров Hadoop
5. Apache He - веб-морда Hive, Spark, Impalas
