NameNode - единственная точка сбоя Hadoop, а QJM (Quorum Journal Manager) значительно повышает надежность HDFS.
### **Как это работает?**
1. Настраивается группы **JournalNodes**, которые записывают каждое изменение сделанное **NameNode**.
2. Когда активный **NameNode** делает изменение, он записывает запись об изменениях в **NameNode**
3. Резервный **NameNode** находится в постоянном режиме чтения этих журналов изменений **JournalNodes** и применяет изименения к своему собственному образу пространства имен в памяти, гаранитуря, что немедленно готов взять на себя управления в случае сбоя активного **NameNode**.
### Архитектура QJM
1) Два **NameNode**
2) Несколько **JournalNodes**. Они обеспечивают синхронизацию **NameNodes**.
3) Узлы **DataNodes** рапортуют обоим узлам **NameNode**, чтобы обеспечить актуальность информации о расположении блоков данных как на активном, так и на резервном **NameNode**
## **Задачи Zookeper**
1. **Управление конфигурацией**. ZooKeeper позволяет централизованно управлять конфигурацией, делая конфигурационные данные доступными для всех ущлов в кламтере. Изменения в конфегурации могут быть мгновенно распостранены по всем узлам, то позволяет системе быстро адаптироваться к новым настройкам.
2. **Синхронизация**. Zookeeper Обеспечивает механищмы для синхронизации действий между узлами в кластере. Это может быть использовано для координации начала и завершения различных операций, гарантируя, что все узлы работают согласованно.
3. **Выборы лидера**. Во многих расрпеделенных системах необходимо определить "лидера" среди группы узлов для управления определенными задачами или для принятия решений от имени группы. Zookeeper предоставляет сервисы для проведения выборов лидера и управления процессом, гарантируя, что в любой момент временеи существует только один активный лидер.
4. **Регистрация сервисов**. Zookeeper может использоваться для отслеживания статуса различных компонентов в системе, предосталвяя регистрацию сервисов и обнаружение. Это позволяет приложениям узнавать о доступности и местоположении различных сервисов в кластере.
5. **Управление распределенными блокировками**. Для того, чтобы обеспечить корректную обработку конкурентных операций в распределенной системе, необходим механизм блокировок. Zookeeper предоставляет API для создания и управления распределенными блокировками, что позволяет разным узлам безопасно работать собзими ресурсами\
6. **Обработка отказов**. Zookeeper помогает системам быстро регаировать на отказы узлов, автоматически переконфигуриря систему для обхода недоступных узлов и минимизации простоев.
