# Apache Spark
Apache Spark - фреймворк для крупномасштабной обработки данных
	- В 100 раз быстрее чем MapReduce
	- Способен работать на Hadoop, Mesos, Kubernetes в автономном режили или в облаке
	- SQL, потоковая и сложная аналитика

### **Компоненты Spark-а**
	![[Pasted image 20240301115215.png]]

**Spark Core** - основная часть фреймворка, предоставляющая основные функции расрпеделенной обработки данныз, в том числе управление памятью, отказоустойчивость, распределение задач и базовый API
**Spark SQL** - модуль для работы с стуктурированными данными. Позволяет выполнить SQL-запросы, используя традиционный синтаксис SQL, а также HiveQL для интеграции с Apache Hive
**Spark Streaming** - Ппредназначен для обработки потоквых данных в реальном времени. Данные могут поступать из разичных источников, таких как Kafka, Flume, Kinesis
**MLlib** - машинное обучение
**GraphX** - библиотека для обработки графов и выполнения графовых вычислений
### **Архитектура Spark-а**
В спарк кластере 2 типа нод:
- Мастер ноды - дирижеры, оркетрируют процессы в кластеры
- Воркеры - предоставляют мощности
Сам спарк разделяют на 2 компанента
	![[Pasted image 20240409114556.png]]
**Driver Program**. Программа, которая создает SparkContext, инициирующий Spark-приложение. Это центральный узел управления, который конвертирует пользовательскую программу в задачи и распределяет их между испольнителями (Executors). Драйвер также отвичает за планирование и сбои
**SparkContext**. Контекст выполнения приложения, управляющий доступом к кластеру через Cluster Manager.
**Cluster Manager**. Менеджер кластера отвечает за выделение ресурсов драйверу и исполнителям.
**Executors**. Процессы, выполняющиеся на узлах рабочего кластера, которые обрабатывают задачи вычислений и хранят данные приложения в памяти или на диске. Executors взаимодействуют с программой "Driver Program" для выполнения кода.
**RDD (Resilent Distributed Dataset)**. Основная абстракция данных в Spark, представляет собой неизменяемую коллекци. элементов, распределенных по кластеру, которую можно обрабатывать в параллельном режиме.
Driver - следит за ходом выполнения задач (выполняет на матсер ноде или на клиенте)
Executor - выполняет задаче (выполняет на воркере)
### План запроса, способы оптимизации запросов
**Логический план** - описывает, что необходимо сделать с данными. Он строится на основе вашего кода и не зависит от конкретной релаизации.
**Физический план** - описывае, как Spark будет выполнять запрос. Spark может генерировать несколько физических лпанов из одного логического и выбирать наиболее оптимальный с помощью своего оптимизатора запросов Catalyst.
	df.explain
### **Способы оптимизации запросов**
**Кэширование данных** - Кэширование часто используемых DataFrame или RDD может значительно ускорить выполнение повторяющихся запросов, минимизируя необходимость повторного выполнения трудоемких операций чтения и вычислений.
**Использование корректных форматов данных** - Форматы данных, поддерживающие сжатие и инжексацию. Например Parquet, ORC, могут значительно ускорить чтение данных и выполнение запросов.
**Скоупленирование и репартиционирование** - Подбор оптимального количества партиций может существенно повлиять на пирозводительность
	df.repartition(100)
	df.coalesce(10)
**Broadcast переменные** - Использование bradcast переменных для "раздачи" небольших датасетов каждому узлу может уменьшить затраты на пересылку данных в кластере.
	from pysparks.sql.functions import broadcast
	df.join(broadcast(small_df), "key")
**Автоматическая оптимизация через SPARK SQL** - Catalyst Optimizer автоматически оптимизирует SQL-Запросы в Spark, но вы можете использовать подсказки для оптимизатора для улучшения производительности определенных запросов.
**Мониторинг и анализ выполнени**
