## Архитектура GreenPlum
	![[Pasted image 20240405151101.png]]
1. **Мастер-узел**. Принимает SQL-запросы, собирает результаты, управляет метаданными и администрированием.
2. **Сегментные узлы**. Хранят и выполняют обработку данных.
3. **Интерконнект**. Сетевая инфраструктура, соединяющая мастер-узел.
### Основные принципы работы и особенности
**Принципы**
	Распределение данных, параллельная обрбаотка и данимаическая настройка нагрузки.
**Особенности**
	Высокая доступность (репликация, автовосстановление + standby master), Горизонатльная масштабируемость, Гибкость и открытость (Hadoop, Spark)
	Кэшируемость данных (для уменьшения операций считывания данных с диска)
### Организация логики хранения данных
**Буферный кэш и ОС кэш**
	Недавно использованные данные сохраняются в кэш, уменьшая кол-во считываний с диска.
								![[Pasted image 20240409132253.png]]
**Глобальный Ресурсный Менеджер**
		В GreenPlum есть RM, которые координирует распределение ресурсов между запросами. Это гарантирует, что каждый запрос или ттранзакция получит необходимые ресурсы.

### Типы таблиц в Greenplum
1. Обычные таблицы (**Heap Tables**). Создаются по умолчанию и поддерживают операции update/delete OLTP
2. Таблицы с разделением (**Partitioned Tables**). Таблицы разделены по диапазону или списку значений дя оптимизации запросов. Разделение улучшает производительность за счет уменьшения количества данных, обрабатываемых в каждом запросе.
3. Таблицы с внешним хранилищем (**External Tables**). Позволяют работаь с данными, которые например в Hadoop
4. Таблицы со случайным распределением (**Randomly Distibuted Tables**). В таких таблицах данные распределеяются по сегментам случаным образом.
5. Распределенные по ключу таблицы (**Hash Distributed Tables**). Таблицы распределяются по сегментам на основе хэш-функции от одного или нескольких столбцов.

### Виды распределения данных по сегментным нодам
1. По хэшу
2. Случайно
3. Реплкации. Полные копии таблицы зранятся в каждом сегменте, это удобно для небольших справочных таблиц.

### Блокировка чтения и записи.
**Блокировка чтения**. 
	MVCC позволяет транзакциям читать данные без блокирования друг друга, предоставляя каждой транзакции "снимок" данных на момент ее начала.
**Блокировка записи**. 
	Когда транзакция изменяет данные, она устанавливает блокировку записи, чтобы предотвратить одновременное изменение этих же данных другими транзакциями. 
**Взаимоблокировки**. 
	Ситуации, когда две или более транзакции блоикруют друг друга.


### Интеграция в Hadoop
Для интеграции с хадооп используется PXF, состоящий из коннекторов и серверной части. На каждый узел GreenPlum устанавливается серверная часть, и к данным идет коннектор.

### gpbackup, gprestore, gptrasfer
**gpbackup** - утилита командной строки, для создания резервных копий баз данных GP.
**gprestore** - утилита для восстановления БД из резервных копий, созданных с помощью gpbackup.
**gptransfer** - утилита для переноса данных между БД Greenplum.

### Интеграция с NiFi и Kafka. GPSS (Greenplum Streaming Server)
	![[Pasted image 20240409132547.png]]
**Kafka** - платформа для обработки потоков данных. Kafka формирует батчи и потом батчи попадают в сегменты.
**NiFi** - система автоматизации потоков данных, которая облегчает перемезение, преобразование и управление данными между системами.

Данные залетают сначала в **Heap storage**, там можно update/delete, OLTP



### Как джойнятся таблицы
**Boradcast JOIN** - меньшая из таблиц передается к каждому узлу и там происходит джоин.
**Redistribute JOIN** - одна из таблиц перераспределеяет по ключу шардирования, так, чтобы на одной ноде были одни и те же данные.
**Hash JOIN** - к одной из таблиц применяется хэш функция и создается хэш таблица. Затем к другой таблице применяется хэш функция и сравнивается значения хэша и происходит JOIN

Сегментация одинаковая у двух таблиц Products и Users, сегментируем по id и Join по id. Тогда Join будет происходитьв рамках одной ноды.

Партиционировать таблицы не только по дате но и по ключу. Иначе одна партиция будет храниться на одной ноду, а лучше если размазать одну партицию при помощи другой партиции и нагрзуим все ноды.
