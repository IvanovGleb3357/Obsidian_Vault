Кафка помогает не потерять аднные между Producer и Consumer:
1. Обмен сообщениями между разными приложениями
2. Потоковая передача данных
3. Ведение журнала (у RabbitMQ этого нет)
	![[Pasted image 20240221232414.png]]
Поэтому на помощь приходит Кафка.
## **Theory**
Сущности:
- Broker
- Zookeeper
- Message(Record)
- Topic/Partition
- Producer
- Consumer

**Broker**
- Прием сообщений
- Хранение сообщений
- Обмен сообщениями
- Можно добовлять разное кол-во брокеров для масштабируемости
Также среди брокеров выбирается **Controller** - обеспечивает консистентность (согласованность и целостность) данных.
**Zookeeper**
- Состояние кластера
- Конфигурация
- Адресная книга (data)
	![[Pasted image 20240221233134.png]]
**Message (Record)**
Стотоит из:
- Key - используется для распределения сообщений по кластеру
- Value - содержимое сообщения - массив байт
- Timestamp - время сообщения (от эпохи). Устанавливается при отправке или обработке внутри кластера.
- Headers - набор key-value пар с пользовательскими атрибутами

**Topic** - stream of data
	![[Pasted image 20240221233453.png]]
**Topic and Patitions** - stream of data. Порядок - First In First Out

Broker хранит в себе Topic-ки.
Producer пишет только в LEADER, а CONSUMER читает только из LEADER
ISR - помогает фоловерам держать в себе записи Лидера.
