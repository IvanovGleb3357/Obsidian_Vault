В ВТБ мой модуль занимался.
Подача заявки на вклад. Физ. лицо заносит свои данные. Мы подтягиваем данные о его счетаз, профиле его лицо (ФИО, почта и т.д.). Создает заявку. Черновик.
Делаем несколько запросов если запросы хорошие то заявка идет на оформление договора.

Может их нужно взять из другой команды, както обработать, изменить. Все выливается в декомпозицию на: задачи на получение инфы, задачи на обработку инфы, задачи на хранение. Интеграция Приложения и CRM - асинхронный SOAP
Интеграция CRM с Комплаенс и Антифрод - асинхронный SOAP. 
Интеграция CRM с Системой Обработки и Регистрации - асинхронный SOAP.

Основная логика - SOAP даст защищту для передаваемых данных.

3) Микросервисная архитектура. Если при большом количестве заявок какая-либо система перестанет справляться с нагрузкой, то мы сможем горизонтально масштабировать наше приложение, уведичив количество экзмпляров микросервисов.
4) Предусмотрел бы внутренний микросервис куда бы отправлял все операции.
5) Если пользователь не подпишет договор. Если система обработки заявки не сможет обработать заявку. Аналогично с системой Регистрации.

6) 
Клиент -> Приложение: id клиента, id заявки, сумма, получатель, валюта

Приложение -> CRM: id клиента, id заявки, сумма, получатель, валюта и параметры для антифрода (геолокация, данные приложения). 

CRM -> Антифрод: id клиента, id заявки, сумма, получатель, валюта и параметры для антифрода (геолокация, данные приложения).
Антифрод -> CRM: передача id заявки, результат проверки

CRM -> Комплаенс: Передача основных параметров: id клиента, id заявки, сумма, получатель, валюта
Комплаенс -> CRM: передача id заявки, результат проверки

CRM -> Система обработки: id клиента, id заявки, отправитель, получатель, сумма, валюта
Система обработки -> CRM: id заявки, результат обработки
CRM -> Приложение: id клиента, id заявки, отправитель, получатель, сумма, валюта, результат обработки
Приложение -> Клиент: id заявки, отправитель, получатель, сумма, валюта, результат обработки, форма для подписания

Клиент -> id клиента, id заявки, результат обработки, результат подписания

Приложение -> CRM: id клиента, id заявки, результат подписания
CRM -> Система Регистрации: id клиента, id заявки, отправитель, получатель, сумма, валюта, данные для антифрода (геолокация, данные приложения), результат антифрода, результат комплаенса, результат обработки, результат подписания.

7) CRM - Система управления взаимоотношениями с клиентами. Антифрод - проверка на мошенничество, Комплаенс - проверка на соответствие регуляторным нормам. К персональным данным может относятся любая информация о клиенте. В рамках системы нужно предусмотреть мехназим защиты передаваемых данных (поэтому используется SOAP), а также невозможность идентифицировать клиентов при утечке информации (для этого используются id клиентов).
