## Веб-сервисы
Это программные компоненты, которые предоставляют возмоность взаимодействия между различными приложениями через сеть, веб-интерефейсы или API.

**Зачем нужны**
1. Интеграция приложений. Веб сервисы позволяют интегрировать различные приложения и системы, обмениваясь данными и функциональностью между ними.
2. Расширение функциональности. Они прежоставляют возможность использовать функциональности и данные других приложений или сервисов без необходимости знать их внутреннюю реализацию
3. Стандартизация коммуникации. Веб-сервисы использует стандартизированные протоколи и форматы данных для обмена инфрмацией, что облегачет интеграцию и взимодействие между различными системами.

 **Протоколы и архитектурные подходы** - REST, SOAP.
 
 ## Терминология
1. **Формат представления данных** (на русском письмо или на английском):
	- Plaint text;
	- XML - язык разметки информаци;
	- JSON - текстовый формат бмена данными;
	- Binary.
2. **Протокол передачи данных** - набор соглашений, которые определяют обмен данными между различными программами. (конверт для письма)
3. **Транспорт** - подмножество сетевых протоколов с помощью которых мы можем передавать данные.
	- HTTP
	- AMQP
	- FTP
Иногда, может присутствовать запись JSON over HTTP, чтобы показать что и через что передается.
## Протколы
1. **IP - Internet Protocol**. Протокол передачи, который первым объединил отдельные компьютеры в единую сеть. Самый примитвный и не следит за консистентностью данных и не гарантирует их доставку.
	Основная задача - маршрутизация датаграмм, определение пути следования данных по узлам сети.
2. **TCP/IP - Transmission Control Protocol/Internet Protocol**. Это стек протоколв **TCP** и **IP**. Первый обеспечивает и контролиуер надежную передачу данных и следит за ее целостностью. Второй отвечает за маршрутизацию для оправки данных. Обычно используется более комплексными протоколами
3. **FTP - File Transfer Protocol**. Протокол передачи файлов. На текущий момент этим протоколом пользуются при удаленном доступе к хостингам. Является надежным и гарантирует передачу данных.
4. **DNS - Domain Name System**. Это не только система доменных имен, но и протокол, без которого эта система не смогла бы работать. Он позволяет клиентским компьютерам запрашивать у DNS-сервера IP-алрес какого-либо сайта, а также помогает обмениваться базами данных между серверами DNS. В работе этого протокола также используется TCP и UDP
5. **HTTP - HyperText Transfer Protocol**. Протокол для передачи произвольных данных в интернете. Протокол клиент-серверного взаимодействия без сохранения промежуточного состояния. В роли клиента чаще всего выступает веб-браузер. Для обмена информацией использует TCP/IP
6. **NTP - Network Time Protocol**. Протокол для синхронизации локальных часов устройсва со временем в сети. Работает поверх **UDP**.
7. **SSH - Secure SHell**. Протокол для удаленного урпавления ОС с использование TCP. В SSH шифруется весь трафик, причем с возможность. выбора алгоритма. Также SSH позволяет обрабатывать любые другие протоколы передачи. Это значит, что кроме удаленного управления компьютером, через протокол можно пропускать любые файли или даже аудио/видео поток.
8. **POP3 - Post Office Protocol**. Почтовый протокол с помощью которого загружаются сообщения на почтовый клиент с удаленного сервера. Таким образом, чтобы прочитать полученное сообщение в почтовом клиенте, вам н нужно подключаться к серверу.

### **Принцип построения и устройства сетевой модели**
Все 7 уровней можно разделить на:
- **Media layers** (уровни среды) L1-L3 - передача информации (по кабелю или беспроводной сети)
- **Host layers** (уровни хоста) L4-L7 - используются непосредственно на устройствах, будь то стационарные компьютеры или мобилные устройства. 

1. **Первый, физический уровень**. Отвечает за обмен физическими сигналми между физчиескими устройствами. Железо.
2. **Второй уровень, канальный**. Решает проблему адресации при передачи информации. Канальный уровень получает биты и превращает их в кадры. Основная задача - сформировать кадры с адресом отправителя и получателя, после чего отправить их по сети использую MAC-адрес.
3. **Третий уровень, сетевой**. На третьем уровне появляется понятие маршрутизация. Для этой задачи созданы маршрутизаторы. Они получают MAC-адрес от коммутаторов с предыдущего уровня и занимаются построением мрашрута от одного устройства к другому с учетом всех потенциальных неполадок в сети.
4. **Четвертый уровень, транспортный**. Его задача это транспортировка пакетов. При транспортировке возможны потери, но некоторые типы данных более чувствительны к потерям, чем другие. Поэтому при передаче данных, наиболее **чувствительных к потерям** используется протокол **TCP**, контролирующий целостность доставленной информации. А вот например для мультимедии небольшие потери не так важны, гораздо критичнее - задержка. Поэтому используется протокол **UDP**. Он **чувствителен к задержкам** и позволяет организовать связь без установки соединения.
5. **Пятый уровень, сеансовый**. Оперирует чистыми данными. Сеансовый уровень отвечает за поддержку сеанса или сессии связи: управляет взаимодействием между приложениями, открывает возможности синхронизации задач, завершения сеанса, обмена информации. *Пример* - видеозвонок по сети. Во время кола необходимо, чтобы два потока данных (аудио и видео) шли синхронно. Когда к разговору дових человек прибавится третий - получится уже конференция. Задача пятого уровня - сделать так, чтобы собеседники могли понять, кто сейчас говорит.
6. **Шестой уровень, представления данных**. Отвечает за преобразование протоколов и кодирование/декодирование данных и шифрование данных.
7. **Седьмой уровень, прикладной**. Уровень приложений. Это то, с чем взаимодействуют пользователи, совего рода графический интерфейс всей модели OSI. Все услуги, получаемые седьмым уровнем от других, используются для доставки данных до пользователя. Протоколам седьмого уровня не требуется обеспечивать маршрутизацию или гарантировать доставку данных когда об этом уже позаботились предыдущие шесть. Основная задача - использовать сови протоколы, чтобы пользователь увидел данные в понятном ему виде.

## Авторизаци, аутентификация, идентификация
**Идентификация** - процедура, в результате выполнения которой для субъекта идентификации выявляется его идентификатор, однозначно определяющий этого субъекта в информационной системе.
**Аутентификация** - процедура проверки подлинности, например проверка подлинности пользователя путем сравнения введенного им пароля с апорлем, сохраненым в БД.
**Авторизация** - предоставление определенному лицу прав на выполнение действий.

***GOOGLE** -Пример*:
1. Система запрашивает логин - идентификация
2. Система запрашивает пароль - аутентификация
3. Система запрашивает смс-ку - двухфакторная аутентификация
4. После этого система дает права - авторизация
